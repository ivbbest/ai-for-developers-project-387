## Git-workflow (правила исполнения)

- Каждая существенная разработка — **отдельная ветка от `main`**: `<тип>/<тема>`
  (`feat/...`, `test/...`, `ci/...`, `docs/...`, `build/...`). Ветка каждого этапа
  указана в заголовке.
- Внутри ветки — **коммит-чекпоинт на каждое существенное изменение**: фиксация →
  проверка (build/тесты) → зелёный коммит → дальше. Сообщение — Conventional Commits,
  ясное, на английском, без внутренних ссылок.
- Ветка пушится и открывается PR — **это делает владелец репозитория** (в текущем
  окружении `git push` исполнителю запрещён); **слияние в `main` — только владелец.**
- **Зависимости**: работа, опирающаяся на неслитую ветку, ставится на паузу до её
  мержа. Независимые работы (этапы 2 и 3) ведутся параллельными ветками.
  Кроме шага 3.5: он зависит от мержа этапа 2 (нужен собранный `frontend/dist`) —
  см. «Порядок и зависимости» (аудит N10/F1).
- **Пересечение пакетов**: ветки этапов 2 и 3 осознанно трогают пакеты смежных
  этапов — `feat/frontend` добавляет стаб `contract/mock-server` (2.1b),
  `feat/backend-api` (3.5) использует `frontend/dist`. Этап 1 мержится раньше,
  это легально; в диффах такие файлы — не «чужие изменения» (аудит N12/F3).
- Перед коммитом — `git diff`: без секретов, PII, мусора и чужих изменений.
- Изменение без тестов соответствующего слоя (см. «Тесты») не считается законченным.

## Тесты (обязательный слой каждого этапа)

Правила: тестируем поведение из контракта, а не реализацию; имя теста —
«что проверяем → ожидаемый результат»; фикс бага начинается с падающего
регресс-теста; PR без тестов своего слоя не принимается. Фреймворки:
**vitest** (unit, бэк), **Playwright** (e2e), Prism/schemathesis (контракт),
in-memory стаб (разработка фронта, 2.1b).

| Слой | Что тестируем (минимум) | Где запускаем | Этап |
|---|---|---|---|
| Контракт | `tsp compile --warn-as-error`; Prism-smoke: все 5 ручек, коды 200/201/400/404/409 (404/409 — через `Prefer: code=NNN`, заготовленный ответ по схеме) | контейнер `node:24`; CI-дифф `openapi.yaml` (1.7) | 1 |
| Бэк: сетка слотов | 15-мин день = 36 слотов, 30-мин = 18; граница 18:00 (`end ≤ 18:00`); прошедшие слоты сегодня исключены; `status` по броням | vitest unit | 3 |
| Бэк: пересечения | 30-мин броня блокирует 15-мин на 09:15 (409); стык 09:00–09:15 + 09:15–09:30 **не** конфликт (касание не пересечение); разные типы конфликтуют; гонка двух POST → один 201, другой 409 | vitest unit + транзакция | 3 |
| Бэк: окно/TZ | дата сегодня+13 допустима, +14 → `slot_out_of_window`; «сегодня» считается в MSK; MSK не имеет перехода на летнее время (DST-краев нет — зафиксировать тестом) | vitest unit | 3 |

переменных с запасными значениями (см. «Локальный запуск»).

## Дробность задач

Правило: **задача = одно поведение контракта + его тест + один коммит**. Дробят не
по времени (оценки субъективны), а по признакам крупности: тест на задачу нельзя
написать до реализации; задача трогает несколько слоёв (спека + код + конфигурация);
коммит содержит больше одного логического изменения; дифф не читается за один проход.
Шаг крупнее (например «сетка слотов») дробится перед началом: 3.2.1 генерация сетки →
3.2.2 произвольный duration и граница 18:00 → 3.2.3 прошедшие исключены → 3.2.4 окно
и его границы → 3.2.5 статус `booked`. Каждый подшаг — зелёные тесты и свой коммит;
так регрессия находится бисектом (`git bisect`/`git log -L`), а не перебором всей фичи.

`4020` стаб) могут быть заняты другими процессами. Перед стартом — проверка занятости
и сдвиг через env, не хардкод:

```bash
# что занято (Linux/WSL):
ss -ltnp | grep -E ':(3001|5173|4010|4020)' || echo "порты свободны"
# задать свободные (пример): обёртка прокидывает эти переменные из хоста
PORT=3101 ./scripts/dev.sh npm run dev -w backend
VITE_API_TARGET=http://localhost:3101 ./scripts/dev.sh npm run dev -w frontend -- --port 5273
PRISM_PORT=4110 ./scripts/dev.sh npm run smoke -w @cal-com/contract
MOCK_PORT=4120 ./scripts/dev.sh npm run start -w @cal-com/mock-server
```

Приложение читает `PORT` из env и на `EADDRINUSE` падает с внятным сообщением
«порт занят, укажи свободный» (см. спеку, «Правила реализации»), а не молча висит.

```bash
# 0) Один раз: dev-обёртка node:24 (шаг 1.2) — все команды ниже внутри неё
# 1) Контракт → OpenAPI (этап 1)
npm run compile -w @cal-com/contract                # → contract/dist/openapi.yaml

# 2) Фронт без бэка — на стабе контракта (этап 2; Prism без состояния — N1)
npm run start -w @cal-com/mock-server         # стаб :4020, сценарий: бронь → «Занято»
npx @stoplight/prism-cli contract/dist/openapi.yaml   # :4010 — smoke по схеме (1.6)
npm run dev -w frontend                       # Vite-proxy /api → :4020

# 3) Фронт + реальный бэк (этап 3)
PORT=3001 npm run dev -w backend            # бэк требует PORT из env (§11.13), seed при старте
VITE_API_TARGET=http://localhost:3001 npm run dev -w frontend   # :5173 → открыть, забронировать слот

# 4) Прод-режим одним процессом (этап 5)
docker build -t cal-com . && docker run -p 3000:3000 -e PORT=3000 cal-com
# → http://localhost:3000 (UI + API). Данные: контейнерный путь backend/data/app.db;
#   на VPS монтируется volume ./data:/app/backend/data (см. deploy-global.md) — брони сохраняются.

# Что попробовать: /book → тип → дата (14 дней) → слот → имя/email → подтвердить;
# второй браузер на тот же слот → «Занято»/409; /admin — бронь в списке;
# /admin/new-type — создать тип «Час» (60 мин) и забронировать его.
```

Команды-заглушки уточняются в README по мере появления пакетов (шаги 2.4, 3.5);
README «Запуск» — часть критериев этапов 2 и 5.
