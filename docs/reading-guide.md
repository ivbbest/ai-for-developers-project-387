# Как изучать проект «Календарь звонков (продолжение)» (путеводитель)

Статус: актуален на 2026-09-06 (курс пройден: шаги 1–6 со следами, релиз v1.0.3,
фича «отмена брони» — issue #12). Обновлять при каждом изменении состава
документации или воркфлоу.

Зачем: быстро погрузиться — понять, что здесь предмет проекта (процесс, а не
продукт), где мы сейчас, как устроены следы работы. Маршрут покрывает: что было
в репозитории изначально, входное задание, решения и план, память проекта.

Главное отличие от предшественника (386): там строили приложение, здесь
**встраивают агента в GitHub-процесс** готового приложения. Проверка результата —
не только зелёные тесты, а **видимый след**: прогон Actions, ответ агента в
issue, коммиты в PR, артефакт отчёта.

## Маршрут изучения для того, кто будет выполнять задачи

Порядок — от «что здесь процесс» к «как выполнять»; в скобках время и
контрольный вопрос.

1. **README.md + `input/user-story.txt`** (25 мин) — прочитать все 6 шагов,
   особенно разделы «Требования».
   Вопрос: чем «тест» в этом проекте отличается от теста в 386? *(след в GitHub)*
2. **AGENTS.md** «Границы действий» + «Специфика курса» (10 мин).
   Вопрос: кто пушит и мержит; почему интерактив не требует prompt, а triage —
   требует?
3. **`.agents/tasks.md`** — любой закрытый шаг со следами (10 мин).
   Вопрос: чем доказан каждый `[x]`? *(ссылкой на run/issue/PR/комментарий или SHA)*
4. **`docs/specs/api-contract.md` + 6 ручек** (20 мин) — достаточно понять
   контракт и сценарий гостя/владельца: агент разбирает жалобы про это
   приложение.
   Вопрос: какой код вернёт повторная бронь занятого слота? *(409 slot_conflict)*
5. **Один прогон в Actions из таблицы README** (10 мин) — открыть лог: кто
   запустил, какие права, что делал агент, чем закончилось.
   Вопрос: зачем `share: false` и фильтр автора в интерактивном воркфлоу?
6. **Блок D** — состояние памяти: где сейчас, что открыто.
   Вопрос: какой следующий незакрытый пункт `tasks.md`?

Далее — работа: берёшь первый незакрытый пункт `tasks.md`, идёшь по «Циклу
исполнения задачи» ниже. Правило курса: не начинать шаг, пока не переформулированы
его «Требования» в чекбоксы с доказательством-ссылкой.

## Цикл исполнения задачи (один виток = один пункт tasks.md)

1. **Взять пункт** из `.agents/tasks.md`; прочитать его источник в
   `input/user-story.txt` (требования/задачи соответствующего шага).
2. **Выполнить** минимально: файл воркфлоу / комментарий / прогон — ровно то,
   что требует пункт, не «расширяя процесс».
3. **Верифицировать следом**: ссылка на run в Actions, URL комментария агента,
   SHA коммита в PR — не «должно работать».
4. **Локальные проверки не отменяются**: правки в репо — прогнать слой тестов
   из AGENTS.md (dev.sh-команды) до коммита.
5. **Коммит-чекпоинт** (Conventional Commits, `git diff` на секреты/PII/мусор);
   пуш/PR — агент, мерж — после зелёных проверок, разбора замечаний и `/oc review`.
6. **Отметить `[x]`** с датой/SHA/ссылкой (только после мержа в main и зелёного
   состояния проекта); итог — в `context.md`; уроки — в конец `mem/learnings.md`.
7. Следующий пункт; смена темы — новая ветка (и мерж предыдущей).

Правила остановки: шаг не закрывается без «следа», даже если всё «логично
настроено»; найдено противоречие между текстом курса и реальным поведением
воркфлоу — править запись в `tasks.md`/памяти с объяснением, а не обходить молча;
каждый новый интерактивный воркфлоу — сразу тест на анти-петлю (ответ агента не
должен запускать агента).

## Как ревьюить следы (вместо «ревью ветки» из 386)

```bash
gh run list --limit 20                      # прогоны: кто/что/когда запускалось
gh run view <ID> --log | head               # что делал агент в конкретном вызове
gh pr view <N> --json comments,reviews      # каналы обратной связи в PR
git log --oneline --format='%an %s' -10     # авторы коммитов: агент vs человек
```

Проверка следа: (1) событие-инициатор совпадает с замыслом шага; (2) прав у
прогона не больше, чем нужно; (3) ответ агента не породил новый прогон
(анти-петля); (4) коммиты агента — Conventional, без ИИ-формулировок.

## Как проверить готовность контекста (маршрут для постороннего)

Ничего не читать из чужого диалога — только репозиторий и команды. Пять шагов,
каждый с ожидаемым результатом; расхождение = находка, её не «объяснять», а
чинить в файле-источнике.

### V1. Целостность рабочего дерева (2 мин)

```bash
git status --short            # чисто
git log --oneline -3          # main = закрытые шаги курса + релизный цикл (тег cal-com-v1.0.3)
git check-ignore -v input/ .opencode/ skills-lock.json .agents/archive/   # все четыре — игнорируются
git config core.fileMode      # false (WSL-права не шумят в diff)
```

Вопрос проверяющему: почему `.agents/` при этом НЕ игнорируется целиком?
*(публичная курируемая память, см. AGENTS.md «Что здесь лежит»; вне git только
`.agents/archive/`.)*

### V2. Факты документов против файлов (5 мин)

Каждое проверяемое утверждение — командой, не на веру:

```bash
# числа тестов/проверок из AGENTS.md и README (после фичи отмены, #12)
grep -cE '^check "' contract/smoke.sh              # 18
grep -cE '^check_body "' contract/smoke.sh         # 12 (всего 30)
grep -cE '^check "|^check_body "' contract/mock-server/smoke.sh  # 53 (+1 ручной «исключена из списка» = 54 PASS-строк в прогоне)
grep -cE '^\s*(test|it)\(' backend/test/*.test.ts  # 77 деклараций; прогон vitest — 78 (цикл now.test.ts генерирует лишний)
grep -cE '^\s*test\(' e2e/tests/booking.spec.ts    # 12
# инварианты opencode-воркфлоу (созданы на шагах 2–5)
grep -E "types: \[created\]|persist-credentials|id-token|share: false" .github/workflows/opencode.yml
```

Ожидание: числа в AGENTS.md/README/tasks.md совпадают с командами; в
`opencode.yml` — фильтр автора и команды, `share: false`, job-level
`timeout-minutes` (параметра `timeout` у экшена нет).

### V3. Покрытие: user-story → tasks.md (10 мин)

Механическая сверка: открыть `input/user-story.txt`, выписать пункты
разделов «Требования» всех 6 шагов (их 28) и для каждого найти чекбокс с
доказательством-ссылкой в `.agents/tasks.md` (итог сверки — таблица 6.10 там же).
Ни один пункт не должен остаться без строки; ни одна строка tasks.md не должна
требовать того, чего нет в курсовом тексте (самодеятельность допустима только
помеченная, как «по желанию»/кандидаты плана).

### V4. Перекрёстная согласованность (5 мин)

- `AGENTS.md` таблица «Что здесь лежит» ↔ фактическое дерево (`ls -a`, `ls docs .agents`);
- ссылки между документами живые: файлов, удалённых из репозитория, в публичных
  доках быть не должно (`grep -rn "docs/archive/" README.md docs` — пусто);
- правила не противоречат друг другу: границы git в AGENTS.md ↔ «Правила ведения»
  tasks.md ↔ ритуалы в MEMORY.md (кто пушит/мержит, Conventional, анти-петля);
- память не расходится с реестром: последняя запись `context.md` описывает
  текущее состояние файлов, «Точка продолжения» указывает реальный следующий шаг.

### V5. Гигиена (2 мин)

```bash
grep -rniE "sk-[a-z0-9]{8}|ghp_[a-z0-9]{8}|xox[bap]-" AGENTS.md .agents docs   # пусто
grep -rn "email\|телефон" .agents/mem/MEMORY.md                            # нет PII
grep -rn "386" README.md                                                   # README ссылается только на 387
```

### Итоговый след

Каждый шаг курса подтверждён зелёными прогонами в Actions (ссылки в
`.agents/tasks.md` и README); `hexlet-check` зелёный на main — автотесты курса
не сломаны.
