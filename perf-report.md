## Главные проблемы

### 1. Max Potential First Input Delay — 380 мс (score 0.21)

Самый длинный задача в main thread определяет максимальную задержку отклика на
ввод. 380 мс — пользователь кликает по слоту или кнопке «Забронировать», а
браузер «думает» почти 400 мс. На бесплатном Render-хосте JS-бандл грузится
медленно, и главный поток занят парсингом/выполнением скриптов. Для календаря
звонков это значит: гость выбирает слот, жмёт — и страница зависает вместо
мгновенного отклика; при повторных кликах теряется ощущение отзывчивости.

**Что делать:** разбить бандл (code-split по маршрутам: каталог, бронь,
админка), деферить некритичные скрипты (`defer`/`async`), оценить lazy-impacts
компонентов формы бронирования.

### 2. Total Blocking Time — 440 мс (score 0.64)

Суммарное время блокировки main thread (задачи > 50 мс между FCP и TTI).
440 мс означает, что в сумме полсекунды браузер не может реагировать на
нажатия, скролл, ввод в поля. Причина та же: неоптимизированный JS-бандл и,
возможно, render-blocking ресурсы.

**Что делать:** убрать unused JS (Lighthouse предлагает экономию 64 KiB),
заменить render-blocking скрипты на `defer`, рассмотреть серверную отрисовку
(SSR) или streaming для начального HTML, чтобы уменьшить объём клиентского
JS до TTI.

### 3. Meta description отсутствует (SEO score 0.9)

Страница не содержит `<meta name="description">`. Поисковые системы не могут
корректно отобразить сниппет, что снижает кликабельность из результатов
поиска. Для сервиса бронирования звонков это прямая потеря органического
трафика: человек ищет «бронь онлайн-звонка» и видит конкурентов с
осмысленным описанием.

**Что делать:** добавить `<meta name="description" content="...">` в
`index.html` или через React Helmet; достаточно одной строки 120–160 символов,
описывающей назначение сервиса.
